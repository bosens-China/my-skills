# 图床实现

## 最小架构

1. 客户端向已认证的业务接口申请上传。
2. 服务端验证用户、文件大小和类型，生成不可猜测且属于该用户的对象 key。
3. 服务端请求仅覆盖该 key 的 `OSS_UPLOAD` 临时密钥。
4. 客户端使用响应中的临时凭证、`s3Bucket`、`s3Endpoint` 直传。
5. 客户端或服务端以已配置的 CDN/自定义域名和经过 URL 编码的 key 生成访问 URL。
6. 仅在需要归属、相册、审核或删除记录时保存数据库元数据。

不要让客户端自行决定任意 Bucket 或任意 key。推荐 key 形如 `images/{user-id}/{yyyy}/{mm}/{random}.{ext}`；随机值使用语言标准库的密码学安全随机源或 UUID。

## 必要边界

- 上传接口要求登录，并按用户限流。
- 白名单至少覆盖实际允许的图片 MIME/扩展名；在服务端限制大小。
- 对 SVG/HTML 等可执行内容单独评估，不默认作为普通图片开放。
- 对重复文件、图片压缩、缩略图、审核、数据库记录和回收站保持 YAGNI；业务明确需要时再加。
- 删除、移动、复制默认走服务端文件 API，不把管理权限下发给浏览器。
- 使用自定义/CDN 域名提供图片，不把可能变化的底层 S3 Endpoint 当作永久公共 URL。

## 验收

- 未登录用户不能取得临时密钥。
- 用户不能上传到别人的 key 或授权前缀之外。
- 过期凭证失败后可重新申请，永久密钥从未出现在网络响应中。
- 上传后的图片可通过配置的访问域名读取，MIME 和缓存头符合预期。
- 非法类型、超限文件、重复 key 和服务端 API 错误都有明确结果。

核心文档：[服务端获取上传临时密钥](https://docs.dogecloud.com/oss/manual-tmp-token)、[获取临时密钥 API](https://docs.dogecloud.com/oss/api-tmp-token)。
