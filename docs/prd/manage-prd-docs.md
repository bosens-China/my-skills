# PRD 文档管理

## 需求生命周期

- 当前决策：把产品需求分为现行决策、未来计划和进行中实施三层。已生效内容进入 `docs/PRD.md` 或 `docs/prd/`，已成型但未开始的内容进入 `docs/plans/`，正在实施的内容进入 `docs/work/`。
- 为什么：分层可避免把当前产品承诺、未来 v2/v3 需求和实施 Todo 混成一个权威来源。
- 边界 / 非目标：只有能独立排期、验收、延期或取消的版本才分开维护。仅为开发顺序服务的 Phase 留在同一进行中需求内；已完成版本不作为永久档案保留。
- 权威入口：[Manage PRD Docs Skill](../../skills/manage-prd-docs/SKILL.md)。

## 计划激活与收口

- 当前决策：开始实施时把计划 PRD 从 `plans/` 移到 `work/` 并创建 Todo，不保留副本。完成后把长期决策合并到现行 PRD，重审下游计划，再删除临时工作目录。
- 为什么：移动而非复制可以保持单一 PRD 权威来源，下游重审可避免未来版本继续依赖失效基线。
- 边界 / 非目标：实现、验证或必要文档未完成时不自动收口；未来计划不仅因长期未开始就被删除。

## 文档与产品导航

- 当前决策：`docs/index.md` 作为文档类别与生命周期地图，只链接现行 PRD 根入口、未来计划、进行中需求和其他文档。`docs/PRD.md` 作为现行产品地图，保留跨模块决策并导航到 `docs/prd/` 模块文档。
- 为什么：分开“有哪些文档”和“产品有哪些模块”，可以避免两份导航重复和漂移。
- 边界 / 非目标：不在 `docs/index.md` 重复枚举产品模块，不在根 `docs/PRD.md` 枚举计划中或进行中需求。已建立的索引不因临时只剩单一 PRD 就自动删除。

## PRD 主题拆分

- 当前决策：当主题拥有独立产品边界、可独立演进或验收、稳定术语或明确跨模块关系时，即使不足 400 行也按模块拆分。400 行仅作为必须审计的软上限。
- 为什么：语义内聚比固定行数更能保证模块可独立理解和维护。
- 边界 / 非目标：不按固定行号切分，不为了拆文件制造没有语义边界的小模块。
